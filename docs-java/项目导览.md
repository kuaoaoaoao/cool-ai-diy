# CoolAI-Java 项目导览

> 一份帮助你快速理解和上手本项目的完整指南

---

## 一、项目概览

CoolAI-Java 是一个基于 Spring Boot 3.2 + Spring Cloud 2023 的 AI 智能业务平台，采用微服务架构，提供以下核心能力：

| 能力 | 模块 | 无API Key可用 | 需要GPU |
|------|------|:---:|:---:|
| 用户认证 | coolai-auth | ✅ | ❌ |
| AI 对话 | coolai-chat | ✅(Mock) | ❌ |
| AI Agent | coolai-agent | ✅(Mock) | ❌ |
| 知识库 RAG | coolai-knowledge | ✅(模拟嵌入) | ❌ |
| TTS 语音合成 | coolai-tts | ✅(Edge-TTS) | ❌ |
| 声音克隆 | coolai-voice | ✅(降级) | XTTS-v2需要 |
| AI 唱歌 | coolai-singing | ✅(降级) | RVC需要 |
| 视频生成 | coolai-video | ✅(Mock) | CogVideo需要 |
| 人物替换 | coolai-deepfake | ✅(Mock) | FaceFusion需要 |
| API 网关 | coolai-gateway | ✅ | ❌ |
| 系统管理 | coolai-admin | ✅ | ❌ |

**核心设计原则：所有功能都有免费/Mock降级方案，零API Key即可启动体验。**

## 二、技术栈

| 层级 | 技术 |
|------|------|
| 框架 | Spring Boot 3.2.5, Spring Cloud 2023.0.1 |

### 第2步：理解 LLM 策略模式 (coolai-common/llm/)

这是项目的核心设计模式，理解它就能理解整个 AI 能力的扩展方式：

```
LlmProvider (接口)
├── MockLlmProvider      ← 无API Key时的模拟回退（始终可用）
├── OpenAiCompatibleProvider ← OpenAI/兼容API
└── AnthropicProvider    ← Claude API

LlmGatewayService ← Provider注册 + 模型路由 + 自动降级
```

**阅读路径**:
1. `LlmProvider.java` — 理解接口契约：`chat()`, `chatStream()`, `embeddings()`, `isAvailable()`
2. `MockLlmProvider.java` — 最简实现，理解每个方法做什么
3. `OpenAiCompatibleProvider.java` — OkHttp + SSE 流式调用
4. `LlmGatewayService.java` — @PostConstruct 自动注入 + 优先真实Provider + Mock回退

```
                                    ├── executePhase()  → MCP工具逐步执行
                                    └── summarizePhase() → LLM总结结果
```

**MCP工具注册**:
```

```

### 第7步：理解知识库 RAG (coolai-knowledge)

```
上传文档 → DocumentParser → TextChunker → EmbeddingService → VectorStore
查询     → EmbeddingService → VectorStore.search() → RRFusion.merge() → LLM生成回答
```

**策略模式链**:
- **DocumentParser**: PdfParser / DocxParser / TxtParser / MarkdownParser
- **TextChunker**: FixedSizeChunker / RecursiveChunker / ParagraphChunker
- **EmbeddingService**: OpenAiEmbeddingService / LocalEmbeddingService
- **VectorStore**: MilvusVectorStore / InMemoryVectorStore

### 第8步：理解各引擎的策略模式

每个 AI 能力模块都采用相同的策略模式：

| 模块 | 接口 | 实现 |
|------|------|------|
| coolai-tts | `TtsEngine` | EdgeTtsEngine (免费), OpenAiTtsEngine, CosyVoiceEngine |
| coolai-voice | `CloneEngine` | EdgeSimulateEngine (降级), XttsV2Engine (GPU) |
| coolai-singing | `SingingEngine` | EdgeTtsSingingEngine (降级), RvcSingingEngine (GPU), DiffSingerEngine, SvcSingingEngine |
| coolai-video | `VideoEngine` | MockVideoEngine, CogVideoEngine (GPU), SvdEngine (GPU), SoraApiEngine (API), WanxApiEngine (API) |
| coolai-deepfake | `ReplaceEngine` | MockReplaceEngine, FaceFusionEngine (GPU), InSwapperEngine, LivePortraitEngine, RoopEngine |

**降级优先级**: 免费引擎 > API引擎 > GPU引擎 > Mock引擎

### 第9步：理解网关和监控 (coolai-gateway, coolai-admin)

- **Gateway**: JWT全局验证 → 白名单放行 → X-User-Id/X-User-Role 请求头传递 → Redis滑动窗口限流
- **Admin**: 系统健康检查、模型列表、配置查看

## 五、核心设计模式

### 1. 策略模式 (Strategy Pattern)

项目中最核心的模式，每个 AI 能力都有接口+多实现：

```java
// 接口定义能力契约
public interface TtsEngine {
    byte[] synthesize(TtsRequest request);
    boolean isAvailable();
    List<String> listVoices();
}

// 多个实现，运行时按配置选择
EdgeTtsEngine     → 调用 edge-tts CLI，免费
OpenAiTtsEngine   → 调用 OpenAI API，需 Key
CosyVoiceEngine   → 调用 Python 脚本，需 GPU
```

### 2. 自动注册 + 降级

`LlmGatewayService` 通过 Spring `@Autowired List<LlmProvider>` 自动发现所有实现：
- 有真实 Provider → 优先使用
- 无真实 Provider → 自动降级到 MockLlmProvider
- `@PostConstruct` 注册 + 日志提示

### 3. GPU Worker 架构

```
Java服务 → RabbitMQ GPU队列 → Python GPU Worker
                              (RVC/XTTS/CogVideo/FaceFusion)
```

GPU 密集型任务不直接在 Java 进程中执行，而是：
1. Java 服务创建任务 → 写入数据库
2. 任务消息投递到 RabbitMQ GPU 队列
3. Python GPU Worker 消费消息 → 执行推理 → 结果回传
4. Java 服务通过 ProcessBuilder 调用 Python 脚本

### 4. AOP 审计日志

```java
@AuditLog(action = "create_conversation", resourceType = "conversation")
public Conversation create(...) { ... }
```

`AuditLogAspect` 自动记录：操作人、IP、时间、参数、结果/异常。

### 5. MCP 工具协议

```java
public interface McpTool {
    String name();           // 工具名称
    String description();    // 工具描述
    JsonNode parameters();   // JSON Schema 参数定义
    JsonNode execute(JsonNode args);  // 执行
    Map<String, Object> toOpenAiFunction();  // 转为 OpenAI Function Calling 格式
}
```

Agent 通过 `McpRegistry` 发现和调用工具，与 LLM 的 Function Calling 对接。

## 九、常见问题

### Q: 不配 API Key 能用吗？
**能！** 项目内置 MockLlmProvider 作为自动回退：
- 对话 → 返回模拟智能回复（根据关键词匹配不同功能介绍）
- 嵌入 → 返回确定性伪向量（基于文本hash，相同输入相同输出）
- TTS → Edge-TTS 完全免费，无需 API Key
- 其他 → Mock 引擎返回示例数据

启动时日志会提示：`⚠️ 未检测到真实 LLM Provider，已启用 Mock 模式`

### Q: 向量检索用的是什么？
优先使用 Milvus（如果配置了），否则自动降级到 InMemoryVectorStore（ConcurrentHashMap + 余弦相似度）。开发环境无需 Milvus。

### Q: GPU 任务怎么执行？
GPU 密集型任务通过 RabbitMQ 队列投递，由独立的 Python GPU Worker 消费执行。没有 GPU 时，相关引擎 `isAvailable()` 返回 false，服务自动降级到免费/Mock 引擎。

### Q: 如何添加新的 LLM Provider？
1. 实现 `LlmProvider` 接口
2. 加 `@Component` 注解
3. Spring 自动注入到 `LlmGatewayService`
4. 无需修改其他代码

### Q: 如何添加新的 MCP 工具？
1. 实现 `McpTool` 接口
2. 加 `@Component` 注解
3. Agent 自动发现并可用
4. 工具会自动转为 OpenAI Function Calling 格式

### Q: 如何添加新的文档解析器？
1. 实现 `DocumentParser` 接口
2. 加 `@Component` 注解
3. `supports(filename)` 方法判断是否支持该文件类型
4. KnowledgeService 自动选择合适的解析器
